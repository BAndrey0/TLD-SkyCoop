# TLD-SkyCoop — кооператив для The Long Dark 2.59

Кооперативное **Выживание** для The Long Dark (Steam, Survival 2.59, build 26312993) на основе
[Sky Co-op](https://github.com/Filigrani/SkyCoop) от Filigrani и адаптации
[SkyCoop-Upadated](https://github.com/DoperDodge/SkyCoop-Upadated) под Unity 6 / MelonLoader 0.7.3.

Сюжетный режим не поддерживается. Мод экспериментальный: перед долгой игрой делайте копию `player\saves`.

Версии 0.15.6–0.16.3 предназначены для Survival 2.59 (Steam build 26312993); старые выпуски 0.15.5 и ниже — для 2.55. Все участники сессии должны обновиться вместе. Лаунчер 1.1.0 создаёт новую копию игры при смене её версии и копирует сохранения, сохраняя прежнюю установку.

## Выпуск 0.16.3

- Исправлена обработка нечисловых значений усталости (`NaN`): они не попадают в память перехода, расход, процент сна и восстановление Силы. Повреждённое значение восстанавливается из последнего корректного в сессии; если его ещё нет — используется 60% усталости. Спринт также защищён от нечисловых значений. Переход сам по себе не считается сном.
- Костюмы переносят направления конечностей и ориентацию ладоней вместо вращений несовместимых осей FBX. Сохраняются длины костей; проверены четыре позы на автоматическом рендере. Невидимые модели не пересчитываются.
- Каждая крышка контейнера имеет общее для сетевого и местного открытия состояние. Повторный `open`/`close` не запускает относительную анимацию ещё раз, противоположное действие ждёт окончания текущего, закрытая поза восстанавливается точно. Содержимое по-прежнему синхронизируется отдельно.
- Целевая популяция животных пересчитывается с детерминированным генератором по текущим условиям; начальный ноль больше не кэшируется на весь игровой день. Следы новых шагов животных передаются пакетами из локации владельца AI; старые следы до подключения не восстанавливаются этим каналом.
- Ускоренная работа не запускает дополнительное затемнение. После её завершения восстанавливаются масштаб времени, освещение и виньетка; предусмотрена очистка зависшего состояния ускорения.
- При запросе подобранного сетевого предмета местная заглушка сразу скрывается, при таймауте возвращается. Для предметов без рабочего окна осмотра есть переход к штатному подбору вместо немедленного повторного выбрасывания.
- Убрана загрузка всех 3D-префабов из F2 ради названий: используется локализация без загрузки моделей. Поиск кэшируется, иконки ограничены кэшем 128 и освобождаются из кэша окна при закрытии. Для неудачных попыток разброса лута введена пауза 0,5 с на неизменившийся спавнер.
- Ограничение FPS: до 120 в мире, 60 в меню/окнах, 30 в фоне, с сохранением более строгого существующего ограничения. Раз в минуту `[Health]` пишет FPS, длительные кадры и расход памяти. Эти изменения снижают нагрузку; исправление всех системных фризов курсора после выхода из игры не подтверждено.

Проверки: 60 автоматических утверждений (включая `NaN`, переходы и повторные открытия), 50 циклов состояния крышки, сборка и рендер четырёх костюмов. Совместная проверка шкафов, следов, освещения и спавна ещё необходима. `tools/render-models.ps1` создаёт автоматический рендер поз без загрузки сохранения, сервера и ручного прохода по меню, с отдельным профилем и самозавершением. Подготовленные ресурсы WINTERMUTE в архив не входят.

## Выпуск 0.16.2

- Пакеты движения объединены (позиция, поворот, анимация, сцена), ограничены 20 обновлениями/с и нумеруются. Steam передаёт их отдельным ненадёжным каналом без накопления очереди; содержимое контейнеров и прочие важные события остаются надёжными. Старые и повторные позы отбрасываются. Сглаживание использует буфер 75 мс и прогноз не дольше 100 мс.
- В меню Esc появилась таблица RTT игроков до хоста. Измерение обновляется каждые две секунды; при задержке движения также показывается возраст последнего снимка. Это прикладной RTT с обработкой игровым потоком, а не ICMP-пинг. У хоста вместо сетевой задержки указано «хост».
- У полных костюмов больше не заменяются координаты каждого сустава координатами другого скелета: сохраняются исходные длины конечностей, передаются вращения и положение таза. Убраны поправки масштаба и высоты классической женской модели для сюжетных костюмов. Визуальное качество всех поз требует повторной игровой проверки.
- Загрузка содержимого контейнера с хоста сохраняет местную позу крышки и не переинициализирует относительную анимацию из открытого положения. Изменение относится и к гостю, и к хосту.

Быстрая проверка без запуска игры: `tools/check-fast.ps1 -Dotnet <путь к dotnet.exe>`. Сборка инкрементальная, зависимости повторно не скачиваются; выполняются 43 проверки политик/пакетов и проверка изоляции ресурсов. Для упаковки с уже установленными зависимостями доступен `tools/package.ps1 -NoRestore`. Полноценный запуск нужен только для конкретной проверки Unity/анимаций, совместная игра этими тестами не подтверждается.

## Выпуск 0.16.1

- Останавливается звук обыска исходного ящика при получении содержимого, отмене и закрытии сетевого контейнера.
- Открывающиеся объекты используют одинаковое направление анимации у всех игроков; повторное открытие/закрытие в том же состоянии блокируется. Палитры автомобилей и других объектов выбираются по стабильному идентификатору места.
- Долгосрочная усталость переносится в памяти сессии через загрузку интерьера и обратно, включая повторную загрузку той же сцены. Это не изменение системы сохранений клиента.
- Целевая популяция животных перестала пересчитываться случайно при каждой проверке. После передачи управления есть пауза перед пополнением, исправлены поздние пакеты прежнего владельца и восстановление AI рядом с навигационной сеткой. Убрано дополнительное перемещение созданного животного к случайной точке маршрута. Добавлена разделка самки оленя `WILDLIFE_Doe`.
- Вместо одной головы можно выбрать полный костюм Маккензи, Астрид, Джеремайи или Молли: при создании персонажа и через F4. Анимации и точки крепления предметов остаются от коопа, движения передаются на скелет костюма. Надетые вещи продолжают влиять на характеристики, но внешний вид костюма не меняют. Классическая модель также доступна.

Костюмы подготавливаются из **ваших локальных ресурсов WINTERMUTE (Episode 5)** при первом выборе. Общий для четырёх моделей кэш хранится отдельно в `player\game\UserData\CharacterSkins` (~420 МиБ); первая подготовка может занять несколько минут. Повторно используются эти файлы; по сети передаётся только номер персонажа. При обновлении исходных ресурсов кэш проверяется и пересоздаётся. Игровые модели и текстуры в публичный архив не входят. Оба игрока должны иметь необходимые локальные ресурсы.

Проверка сборки: 32 автоматические проверки политик сессии и переноса усталости; все четыре костюма загружены в тестовую сцену, по 52 сопоставленные кости. Совместная проверка передачи животных между регионами, многократного открытия капотов и звука контейнеров остаётся обязательной: выпуск экспериментальный.

## Выпуск 0.16.0

Лаунчер 1.1.0 получил новый интерфейс, отдельный экран установки/DLC, проверку SHA256 загрузок и синхронизацию установленных дополнений из вашей Steam-копии перед запуском. Синхронизация копирует изменённые файлы `tld_dlc`, проверяет их хеши и не создаёт ещё одну полную копию игры.

Клиент сообщает хосту о готовности своей локации, чтобы получить управление животными без предварительного посещения этой локации хостом. Исправлен поиск региона спавна при ответе сервера на запрет спавна. Сценарий с двумя игроками в разных регионах требует игровой проверки.

Переработаны Сила, расход усталости на канате и завершение ускоренной работы. Длинные рецепты расходуют больше 100 Силы за несколько подходов. Расчёты, ограничения и проверки: [баланс 0.16](docs/BALANCE-0.16-RU.md).

В 0.16.0 F4 выбирал только голову. Начиная с 0.16.1 применяется полный сюжетный костюм (см. выше).

Tales from the Far Territory должен быть установлен у каждого участника, использующего его контент. Наличие файлов DLC не подтверждает синхронизацию всех его новых механик; сюжет WINTERMUTE по-прежнему не поддерживается.


## Установка для игроков

**Проще всего — лаунчер.** Скачайте `TLD-Coop-Launcher.exe` со страницы [Releases](../../releases), положите в пустую папку с латинским путём (например, `D:\TLD-Coop`) и запустите. Лаунчер сам найдёт игру в Steam (или спросит папку), сделает отдельную копию, поставит MelonLoader, .NET 6 и мод, будет подтягивать обновления и запускать игру кнопкой «Играть». Это те же шаги, что ниже, только без ручного запуска скриптов. Если раньше ставили через `Install.cmd`, положите лаунчер рядом с папками `friend-kit` и `player` — он подхватит готовую установку.

Вручную:

1. У каждого игрока своя Steam-копия The Long Dark **версии 2.59** (build 26312993) и запущенный Steam.
2. Скачать архив `TLD-SkyCoop-<версия>.zip` со страницы [Releases](../../releases) и распаковать в папку
   с латинским путём, например `D:\TLD-Coop` (получится `D:\TLD-Coop\friend-kit`).
3. Запустить `friend-kit\Install.cmd` и указать папку игры Steam, если её не нашло само.
   Установщик:
   - делает **отдельную копию игры** рядом (`D:\TLD-Coop\player`, ~21 ГБ) — оригинальная игра и её сохранения не трогаются;
   - скачивает с официальных страниц MelonLoader 0.7.3, .NET 6 runtime и ресурсы Sky Co-op v13.2 и проверяет их хеши;
   - кладёт моды из `friend-kit\files`.
4. Играть через `player\Play-Coop.cmd`.

**Обновление:** распаковать новый архив поверх, заменив `friend-kit`, и запустить `friend-kit\Update.cmd`.
Папку `player` (там сохранения) не удалять. Версии у всех игроков должны совпадать — сервер не пускает другую.

Как играть, что изменено и известные ограничения — в [kit/README-RU.md](kit/README-RU.md) (этот же файл лежит в архиве).

## Консоль для проверок

F2 открывает окно предметов: сетка всех предметов игры (каталог из таблиц автодополнения консоли игры) с иконками, поиском, вкладками по типам и выбором количества; клик кладёт предмет в инвентарь.

F1 открывает консоль, если это разрешает настройка сервера «Читы» (0 — никому, 1 — только хосту, 2 — всем; вне коопа всегда). `give <GEAR_имя> [кол-во]` кладёт предмет в инвентарь, доступны и команды игры: `gear_add`, `add_all_gear`, `god`, `fly`, `set_time`, `map_reveal`, `afflictions_cure`, `spawn_wolf` и др. В релизной 2.59 нет объекта консоли игры, поэтому мод рисует своё окно и запускает зарегистрированные команды напрямую.

## Что исправлено относительно SkyCoop 0.14.1

- **Общий разбросанный лут.** Мод делает лут одинаковым у всех через сид, в который подмешивался
  `string.GetHashCode()` — в .NET 6 он случайный в каждом процессе, поэтому у каждого игрока лежали разные вещи.
  Заменён на детерминированный хеш (`Shared.StableHash`); то же для ключей брошенных/переданных предметов.
- Выбор сложности запускал испытание: режим брался по номеру строки меню из списка всех режимов игры.
- «Назад» в лобби оставлял меню в неработающем состоянии; «Назад» на карте регионов ничего не делал.
- Луч электрического фонарика другого игрока не отображался (код синхронизации не был подключён).
- В обысканный контейнер нельзя было положить вещи — повторное открытие теперь показывает окно переноса.
- Старт сервера падал из-за животного без `ObjectGuid` — друзья не могли подключиться.
- Регион в интерьерах определялся по куску имени сцены (`HouseBasementPV` → Тихая долина).
- Выбор персонажа при входе открывался до 5 раз из-за повторных пакетов.
- Ветки, камни и перья не синхронизировались даже с выключенными дубликатами.
- Порча вещей была выключена всегда — теперь настройка `EnableItemDecay` (раздел `[SkyCoop]` в `UserData\MelonPreferences.cfg`).
- Клавиши мода (Esc для отмены обыска и др.) читаются и через ввод игры, если старый `UnityEngine.Input` недоступен.
- Подключение по IP могло брать IPv6 link-local адрес; спам «No ViewModelRadio mesh» в логе; сторож записи на диск при выходе.

## Сборка из исходника

Исходник получен декомпиляцией SkyCoop 0.14.1 (ILSpy) и правится как обычный C#-проект.

Нужно:
- .NET SDK 6+ (подойдёт 8.0);
- установленная через `Install.cmd` копия игры, хотя бы раз запущенная: MelonLoader генерирует в
  `player\game\MelonLoader\Il2CppAssemblies` сборки игры, на которые ссылается проект. В репозитории их нет.

По умолчанию проекты ищут игру в `..\..\player-2.59\game` относительно себя, то есть репозиторий удобно клонировать
рядом с `player`: `D:\TLD-Coop\TLD-SkyCoop`. Иначе укажите путь явно:

```
dotnet build SkyCoop\SkyCoop.csproj -c Release -p:GameDir=D:\TLD-Coop\player\game
```

Собрать архив для игроков (DLL, manifest с хешами, скрипты, лицензии):

```
powershell -ExecutionPolicy Bypass -File tools\package.ps1 -GameDir D:\TLD-Coop\player\game
```

Результат — `out\TLD-SkyCoop-<версия>.zip`. При изменении сетевого протокола поднимайте версию (строки `0.14.x`
в `SkyCoop`), иначе игроки с разными сборками смогут подключиться друг к другу.
